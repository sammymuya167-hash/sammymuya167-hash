Task 3: Mathematical Functions and Vectorization

1. Original Problem

The program simulates one million network-latency readings in
milliseconds. It converts each reading to seconds, squares the
value, and compares the execution time of a normal Python loop
with NumPy vectorized computation.

2. Inputs

The program uses the following inputs:

- Random-number generator seed: 42.
- Range of simulated latency readings: 5 ms to 250 ms.
- Number of readings: 1,000,000.
- NumPy is used to generate and process the readings.

The random seed makes the simulated data repeatable.

 3. Mathematical Operations

For each latency reading L measured in milliseconds, the program
performs two mathematical operations.

## Step 1: Convert milliseconds to seconds

seconds = L / 1000.0

### Step 2: Square the value

squared = seconds ** 2

The program performs these calculations using two approaches.

### Loop Version

The loop processes each latency reading individually and adds
the squared result to a Python list.

### Vectorized Version

The vectorized version uses NumPy to divide and square all the
readings without writing an explicit Python loop.

## 4. Output and Interpretation

The program displays the following outputs:

- The first five squared latency values.
- The execution time of the loop version.
- The execution time of the vectorized version.
- The approximate speed-up of vectorization.

The squared latency values are expressed in squared seconds (s²).

The loop time indicates how long the loop-based calculation takes.
The vectorized time is the average execution time across three runs.

The approximate speed-up is calculated by dividing the loop time
by the vectorized time.

If the speed-up is greater than 1, the vectorized version was
faster in that particular measurement.

Execution times depend on the computer and other running programs.

## 5. Change One Input and Explain the Effect

In the original program, the number of simulated readings is
1,000,000.

Original line:

latency_ms = rng.uniform(5, 250, 1_000_000)

Change it to:

latency_ms = rng.uniform(5, 250, 500_000)

This reduces the number of readings from 1,000,000 to 500,000.

### Expected Effect

1. Both methods have fewer readings to process.
2. The execution times will generally decrease.
3. The first five readings should remain the same because the
   random seed and range have not changed.
4. The speed-up ratio may change depending on the computer.

The exact execution times should be recorded after running the
program.

## 6. Related Real-World Application:
## Computer Lab Network Monitoring

The modified program, Task_03_lab_network_monitoring.py,
represents a computer lab monitoring simulated network latency.

It calculates the minimum, maximum, and mean latency, converts
the mean latency to seconds, and compares loop-based and
vectorized calculations.

### New Assumptions

- The readings are simulated and are not collected from real
  computer lab devices.
- Each reading represents network latency in milliseconds.
- The program uses 100,000 readings to keep the demonstration
  manageable.
- The random seed is 42 so the simulation can be reproduced.
- Squared latency demonstrates the mathematical operation and
  vectorization. It is not itself a standard measure for deciding
  whether network latency is acceptable.

### Inputs

- Simulated latency range: 5–250 milliseconds.
- Number of readings: 100,000.
- Random seed: 42.

### Outputs

The program displays:

- Number of simulated readings.
- Minimum latency in milliseconds.
- Maximum latency in milliseconds.
- Mean latency in milliseconds.
- Mean latency in seconds.
- First five squared latency values.
- Loop execution time.
- Vectorized execution time.
- Approximate speed-up.

### Interpretation

The mean latency summarizes the simulated network readings.

The minimum and maximum show the range of latency values
generated by the simulation.

The loop and vectorized execution times demonstrate the time
taken by each calculation method on the computer running the
program.

Vectorization will often be faster when processing large arrays,
although actual performance depends on the computer and the
conditions under which the program runs.
