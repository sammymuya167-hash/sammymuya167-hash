# RouteForge scheduled retries

This small Worker belongs to the existing RouteForge codebase. It resumes due dispatch, missing status events and merchant callbacks in the authoritative RouteForge Site; it does not host another application or database.

`wrangler.jsonc` declares the verified RouteForge origin and one-minute UTC Cron. A separate random 32-byte hexadecimal `ROUTEFORGE_JOB_KEY` must be stored as a secret on both the existing Site and this Worker. Never commit a `.dev.vars` file, credential or signature. The current Cloudflare connection can deploy this component but cannot manage the Site provider's dispatch namespace.

Release procedure:

1. Run the repository typecheck, lint, tests, production build and built-Worker integration checks. The tests exercise the actual Miniflare scheduled handler, signed egress, tenant-independent service authorization and fail-closed responses.
2. Save and deploy the verified pushed Site version with the protected `/api/internal/network-tick` endpoint and its new job secret. Preserve its database, original environment entries and audience.
3. Upload `worker.mjs` through the connected Cloudflare Workers API with the metadata from `wrangler.jsonc`, the exact origin as a plain-text binding and the matching job key as a secret binding. Do not enable a schedule before the Site service is available.
4. Invoke the Worker's POST endpoint using `X-RouteForge-Job-Timestamp` (Unix seconds) and `X-RouteForge-Job-Signature` (lowercase hex HMAC-SHA256 of `timestamp + "." + exact raw body`, using the job key), with body `{"operation":"tick"}`. Confirm the persisted successful heartbeat through the similarly signed Site service operation `{"operation":"status"}`.
5. Configure the Worker's schedule as `[{"cron":"* * * * *"}]` and read it back. Check a later heartbeat or the Worker logs to verify actual Cron execution. Administration flags a heartbeat older than three minutes for investigation.

The public Worker GET reports its service name and disabled live payments only. It does not execute work. Merchant API keys and office cookies cannot run the protected service. Successful logs include time/outcome/count only. The Worker rejects upstream redirects and any configured origin other than this RouteForge Site. Scheduled handler failures remain visible as failed invocations; the next minute retries durable due work under database leases.

For an immediate reversible pause, set this Worker's schedules to an empty array; active RouteForge clients can still resume due work. To pause new network activity use the existing Site's network feature flag while retaining authorization and already assigned completion paths. Rotate the job secret on both services together. Do not drop tables, replace the Site or roll back its staff permissions.

The compatibility date matches the existing application runtime (`2026-05-15`). Binding types are generated by Wrangler. The ignored local `.dev.vars` used for type generation contains a synthetic test key only.
